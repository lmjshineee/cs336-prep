## 3. 首先修正哪些表达

### 3.1 先学一个完整模型

GPT-2 课程默认只出现 GPT-2。目录、账本、公式、源码、镜头都围绕它组织，减少同时辨认两套模型的负担。LLaMA 与比较视图保留为后续独立入口，不删除已有内容或学习记录。

采用独立 HTML 学习页面，共用必要的场景、控件和构建代码，不拆成两个重复维护的项目。GPT-2 页面不显示另一座塔、双列参数账本或跨模型课程步骤。当前目录暂不改名，避免先引入路径和存储变化。

### 3.2 让真实轨迹成为主要实例

当前 `js/trace.js` 的注意力由确定性随机算法生成；分词、生成词与概率也有教学设定。新课程中的主要实例改为 Python 真实运行导出的轨迹。原手算例子保留为独立的“手算示例”，继续允许修改输入，帮助理解公式。

不在真实轨迹上允许随意修改 Q/K/V 后仍显示原模型输出。若开放干预，必须明确说明重新计算范围和后续数据是否失效。

### 3.3 按代码执行顺序讲输出头

当前图谱简化成“先取最后位置，再进入输出头”。本地 `GPT2.forward` 实际返回所有输入位置的 `[B,T,V]` logits，生成函数再取 `logits[:, -1, :]`。主教学轨迹应与这套实现一致；只计算最后位置的做法若以后出现，应标为另一种执行选择。

### 3.4 缓存同时解释容量和有效内容

当前图谱用 fp16 和有效 token 数推导缓存字节数。本地实现默认 fp32，并按最大长度预分配 K/V 张量。

因此应区分：

- 已分配容量：创建缓存后已经占用的张量存储。
- 有效内容：本轮已写入、可以被读取的位置。
- 本轮读写：本次执行访问或新增的切片。

字节数从实际张量的 `numel()` 和 `element_size()` 取得，不继续把固定 fp16 公式当作实测值。按默认形状计算的 K/V 容量是 72 MiB；代码注释中“75 MiB”需要在材料核对时记录，避免照抄。原代码本轮不修改。

形状默认显示 batch 维；若局部图省略 B=1，应就地说明。

### 3.5 不把可见模式直接解释成因果机制

观察到某个头对重复片段赋予高权重，可以讲这次输入中的模式；不能只凭热图认定该头负责某种语义，或证明模型输出由它决定。消融与干预留作独立实验。

原实验说明中的复杂度、耗时、跨语言困惑度与“复制头”结论也需逐项核对条件，再转写成教学内容。

## 4. 第一条学习路径

先选一条短输入作贯穿实例，具体句子由真实分词与输出检查后确定。完成一次 prefill 和少量 greedy decode，再引入不同输入。

| 顺序 | 核心问题 | 展示方式 | 对应代码 |
|---|---|---|---|
| 1 输入 | 文本怎样变成整数？空格和标点怎么处理？ | 原文片段、token 表示、ID、位置联动；中文按字节边界谨慎展示 | `load_tokenizer` |
| 2 嵌入 | 一个 ID 如何成为 768 维向量？ | 词嵌入与位置嵌入相加；默认显示明确标注的维度切片 | `GPT2.forward` |
| 3 一个 Block | 残差主干与两条更新支路怎样工作？ | 固定一个层，逐步展开 LN→Attention→Add→LN→MLP→Add | `Block.forward` |
| 4 注意力 | 一个位置怎样读取前面的位置？ | QKV 投影、split、reshape、transpose、scores、mask、softmax、加权 V、输出投影 | `CausalSelfAttention.forward` |
| 5 MLP | 每个位置内部怎样做非线性变换？ | 768→3072→768，tanh 近似 GELU；与残差前后向量联动 | `MLP.forward` |
| 6 输出 | 最后位置如何给出下一 token 分数？ | final LN、全位置 logits、最后位置切片、概率和候选 | `GPT2.forward`、`_next_token` |
| 7 生成与缓存 | 选出的 token 怎样成为下一轮输入？ | prefill/decode 切换、position、逐层 cache 有效范围、分配容量 | `generate_cached` |

完整 12 层通过结构图定位，默认只深入一层。保留跨层切换，但不要求首次学习逐项读完所有层。

## 5. 页面与数据方案

### 页面

- 左侧为课程与当前步骤。
- 中间为结构概览或当前计算图；深入计算时给矩阵足够空间。
- 右侧按需查看解释、源码和数据，不常驻三套长文本。
- 点击代码中的一个操作，定位对应图；点击张量，显示形状、数值切片和生产它的操作。
- 全局只保留理解当前状态所需的信息：模型、实例、阶段、层、头和位置。运行环境及哈希放到可展开的来源详情。

代码阅读要讲清 `split/view/transpose/contiguous` 等实际操作，不能仅用一段抽象公式代替实现。源码展示使用经过核对的本地快照，标明来自个人实现；与参考实现和官方权重来源分别记录。

### 数据

优先采用：

`本地 Python 实现与权重 → 受控导出 → 可验证轨迹 → 浏览器回放`

首版不用浏览器加载数百 MB 权重，也不需要每次打开页面启动 Python。继续支持离线单 HTML；页面明确显示所选实例是一次真实运行的回放。任意文本实时推理是独立的后续功能。

导出适配器放在可视化项目内，读取原实现；原代码、权重、历史 runs/figs 保持原状。通过适配器或限定的观察入口采集数据，导出前后核对最终输出没有因采集改变。

每条轨迹至少保存：

- 稳定实例 ID、文本、token ID、位置和生成 token。
- 实现文件哈希、配置、权重与 tokenizer 指纹、库版本、设备、dtype、eval 状态、采样策略及种子。
- 每步操作 ID、源码符号、张量完整形状、真实数据或切片说明、缓存有效范围及容量。
- 数据关系：prefill、decode、层、头、位置之间的对应关系，避免套用固定九词的旧索引。
- 对齐检查结果、容差与参考实现身份。

先定义采集预算：短输入保留全部注意力矩阵；中间 Q/K/V、残差与 MLP 优先采集一个完整 Block。其他层按明确策略保存摘要，未采集内容不伪装成可查看的完整数据。负无穷掩码值采用明确编码，避免非法 JSON。

概率图不能把 Top-N 重新归一化后冒充全词表概率，应保留其余概率质量。若允许调温度或 top-k，需要保留足够的原始 logits。更换采样结果后，原轨迹的后续 token 不再适用；首版只演示当前步的分布变换，后续仍按原采样策略回放。

### 9.3 内容和界面规范

### 10.1 数据组织

建议在项目内新增 `tools/trace/`、`data/gpt2/`、`sources/gpt2/`。文件职责如下，名称允许在 S0 小范围内调整并记录：

| 文件 | 用途 |
|---|---|
| `tools/trace/export_gpt2.py` | 导入上一级模型，运行限定实例，采集和导出 |
| `tools/trace/verify_gpt2.py` | 核对参考实现、导出前后等价、张量与事件不变量 |
| `data/gpt2/manifest.json` | 实例索引、schema 版本、文件摘要、来源关系与检查结果 |

Python 读取路径通过参数指定，默认指向已找到的 `real_llm_lab`，不修改上级目录的代码、权重、环境和实验输出。依赖缺失时先报告；安装或升级依赖需列入明确范围。模型加载使用本地文件，不自动联网下载。

### 10.2 结构字段

| 对象 | 必需信息 |
|---|---|
| `provenance` | 实现、配置、权重、tokenizer 的哈希；参考实现与依赖版本；CPU/设备、dtype、eval、种子、生成策略；导出工具版本和运行时间 |
| `input` | 原文、完整 token IDs、token 原始表示、位置和可核对的字节映射；无法按字符切分时标明 |
| `events` | 稳定 ID、执行序号、阶段、层、操作、读写张量 ID、源码符号和可回放状态 |
| `tensors` | 原始 shape、轴名、dtype、载荷类型、存储 shape、切片范围、统计范围、数据引用 |
| `generation` | 每次使用的 logits 行、greedy/采样策略、选中 token、追加位置、对应后续前向 |
| `cache` | 逐层已分配 shape/bytes、当前有效区间、本次写入区间、读取区间 |
| `validation` | 比较对象、检查种类、最大误差、绝对/相对容差、通过/失败/未验证及原因 |

### 10.3 默认实例和采集预算

- 主实例候选：已有 parity 输入 `The cat sat on the mat.`，使用真实 tokenizer 确定长度，不硬编码成九词；若其生成不适合教学，S0 记录替换理由。
- 生成观察目标：三个新 token，先用 greedy；导出执行事件数以实际函数调用为准。
- 辅助实例一：已有计数序列，观察较集中的下一 token 分布。
- 辅助实例二：重复英文片段，观察跨层跨头注意力；作为 S6 增补，不挡主路径交付。
- 主实例每次前向保留全部层、全部头的注意力矩阵；一个选定 Block 保留完整主要中间张量。选定层在 S0 固定并记录，默认可用第 0 层。
- 所有层显示实际结构与已采集摘要。只有选定 Block 可深入其 Q/K/V、LN、残差和 MLP 数值；切到未完整采集的层时明确可查看范围，不沿用另一层的数据。
- 模型输出原始 `[B,T,V]` 形状与执行事实保留；导出前核对全输出，页面载荷优先只保留生成使用的最后一行完整词表 logits。其余位置不提供未采集的数值查看。
- 首版不导出整份参数矩阵、全部层 MLP 完整激活或缓存预分配区的零数据。完整已分配容量作为实测描述保存，所需有效 K/V 或切片另外保存。
- 优先采用 float32 二进制载荷加明确的 base64 编码，保留 shape、轴顺序和字节序；JSON 元数据与载荷可独立检查。masked scores 用掩码加有效分数表达，禁止把 NaN/Infinity 直接写进 JSON 或默默替换为零。
- 完整单 HTML 体积目标不超过 15 MiB；超过 20 MiB 时暂停增加实例，先报告组成并调整采集预算。任何压缩或降精度都需记录并验证误差，不能只为体积改变概率或排名。

### 10.4 采集必须忠实于执行

优先使用 forward hooks 采集模块输入输出；`split/transpose/scores/mask` 等函数内中间值不能仅凭模块 hook 取得，需要限定的观察包装或等价采集适配器，并与未采集的原实现作输出核对。不得悄悄替换模型计算再把结果标成原实现的逐步执行。

采集张量应 `detach` 并复制到独立存储，避免缓存原地写入导致所有历史步骤指向最终值。采集器须恢复临时状态、钩子和 record 开关，使用受控输出目录，失败时留下明确失败记录而非可发布的半份轨迹。

特别核对生成边界：当前 `generate_cached` 循环可能在最后一个采样后继续执行一次前向，该 logits 不再用于本次生成。事件账本必须保留真实调用，并标明输出是否被后续选择使用。课程可折叠这类额外步骤，但不能把简化后的流程声称为源代码的逐行回放。输出 token 追加、各层 K/V 写入和下一次预测之间的时间关系均按实际事件推导。

### 10.5 前端真实数据边界

- 页面只有一个状态来源：当前实例和事件。层、头、位置、形状、缓存及概率由其派生，跳转和倒退不能累加修改缓存。
- 换实例暂停播放、重置合法选择并刷新全部面板；旧头或位置超界时回到有效值。
- 缺数据、版本不支持或校验失败时暂停该实例并说明原因；保留独立手算例子可访问，不用模拟数据冒充恢复成功。
- 真实轨迹不允许修改 Q/K/V。手算例子独立拥有可编辑输入和自己的计算结果。
- 温度和 top-k 是当前步的分布实验，不修改已记录的生成路径。首版不提供“换一个 token 后继续播放原后续结果”的操作。
- 概率条保留其他 token 的总质量。全词表归一化、排名与熵使用完整保存的 logits，不能用显示的 Top-N 代替。
- 真实 token 的原始符号、字节和解码文本分别处理；单个 token 不一定能独立解码成完整字符。输入和源码均转义显示。

## 11. 课程与交互的详细安排

沿用九个概念 ID，修订内容如下。课堂主线先走输入、一个 Block、堆叠、输出和生成，再专门解释缓存。

| 课程 ID | 内容调整 | 必须完成的互动 |
|---|---|---|
| `read` | 只看 GPT-2；认识输入、12 个 Block、输出头 | 选择一个 Block，在局部计算与整体定位之间返回 |
| `tokens` | 真实 tokenizer；token ID、位置；词嵌入与位置嵌入相加 | 选择一个真实 token，核对 ID、位置及向量切片 |
| `attention` | 真实层/头/位置；QKV 到输出投影；展示 head 重排 | 选一行核对 mask、权重和为 1；打开手算例子理解同一公式 |
| `residual` | 两次 pre-LN、残差主干；实际 LayerNorm 参数与维度 | 对照同一位置的输入、更新项和相加结果 |
| `mlp` | GPT-2 的 768→3072→768 与 tanh 近似 GELU；移出 SwiGLU | 查看一个分量的激活变化和两次线性投影的形状 |
| `params` | GPT-2 单列账本；与 Python 参数遍历核对；共享输入输出权重 | 追溯一个分项到真实参数名和 shape，核对共享权重未重复计数 |
| `generate` | 全位置输出与最后位置切片；logits、概率、greedy | 找到真实下一 token，解释它来自哪一行输出 |
| `cache` | 对照 prefill/decode；容量、有效长度、写入与读取 | 前进和倒退一次，解释新 token 何时进入每层缓存 |
| `summary` | 用同一实例复述完整 GPT-2 回路；LLaMA 另作入口 | 从原文沿着实际计算走到一个生成 token，并定位源码 |

答题题目只核对已讲过的概念；答错后能查看当前实例和重试。课程时长等到实际内容和试学后再估计，不沿用旧“30 分钟”作为完成承诺。

布局验收：1440×900 作为主要阅读尺寸，1280×720 保证完整操作；768×1024 和 390×844 保证入口、阅读、步骤与必需控件可达。窄屏一次显示当前图或当前解释，完整手机体验仍需真实设备试用。

| 回放 | 任意跳转/倒退与直接查原事件一致；面板共享同一状态 | 修复状态推导，禁止靠重载页面掩盖 |
| 解释 | 执行顺序、shape、缓存、来源、切片范围与代码一致 | 改文案或数据表达，不改事实迎合图示 |
| 页面分离 | GPT-2 与 LLaMA 独立创建、显示和导航，无隐式跨模型教学 | S2 不通过 |
| 学习记录 | 原键不变，新键隔离，旧历史不冒充新课程通过，导入导出可恢复 | 阻止覆盖正式使用版本 |
| 离线 | 两个入口和 GPT-2 数据/源码独立打包，离线冷启动可用 | 构建交付不通过 |
| 可操作性 | 规定视口、键盘、弹窗焦点、矩阵滚动和缩放可达 | 记录具体失败范围并修复 |
| 稳定性 | 无未处理错误，失败提示可恢复，按需渲染保持 | 修复并重验相关路径 |
| 学习效果 | 用户能定位数值来源、解释一轮生成和缓存状态 | 保留待试学状态，按实际卡点调整 |

不再以固定的“多少项测试通过”代替结论。每项检查记录覆盖对象、输入条件、结果和限制；仅在变更、失败或未决问题需要时重复或扩大检查。
