## 1. 需要修正的问题

### R1 · P1：GPT-2 总览显示为 30 层 Llama / SwiGLU / RMSNorm

- 位置：`GPT2-LLaMA-Atlas/js/spec.js:393–394`。
- 触发：打开 GPT-2 页面，查看默认根节点右侧作用说明。
- 实际：显示“OpenAI 的 GPT-2 Small：decoder-only Llama 架构，30 个 Block 重复，自注意力 + SwiGLU，外面包着残差与 RMSNorm”。同一页面事实表仍为 12 层，与课程和实际模型矛盾。
- 原因：通用 `buildModelNodes(c)` 中将 SmolLM2 的介绍写成所有模型共用的字面文本。
- 修复建议：依据当前配置或独立模型介绍生成说明，GPT-2 为 12 层、LayerNorm、GELU；旧 LLaMA-2 和 SmolLM2 也分别核对层数。新增针对不同模型根节点可见文案的检查。
- 验证：独立浏览器复现；截图 `output/playwright/review-20261031/gpt2-desktop.png`。当前 111 个测试没有覆盖此文案串用。

### R2 · P2：RoPE 面板的 Q/K 头配对不符合 GQA

- 位置：`GPT2-LLaMA-Atlas/js/llama-local.js:54`。
- 触发：第 0 层 RoPE 面板切换 Q 头，尤其界面选择“Q 头 2”（内部 head=1）。
- 实际：`kHead=Math.min(head,2)` 给出 `[0,1,2,2,2,2,2,2,2]`；真实 GQA 应为 `[0,0,0,1,1,1,2,2,2]`。因此 5 个 Q 头展示了错误组 K 的旋转前后值，与 KV 共享页面相互矛盾。
- 原因：将截断头索引当成分组映射。
- 修复建议：按 `floor(head/(H/Hkv))` 映射，并核对全部 9 个头。不能仅测默认 head=0。
- 验证：独立读取实际载荷和浏览器交互均复现。每组 K 自身的旋转重算误差仍很小，所以“Q/K 重算通过”并不能发现配错组的问题。证据在最终浏览器报告的 mapping 数组与 `llama-rope-head2.png`。

### R3 · P2：RoPE 课程第 4 步打开了未采集的 L1 细节

- 位置：`GPT2-LLaMA-Atlas/js/llama-lessons.js:44`。
- 触发：RoPE 课程 `rope.s4`，该步定位 `cycle=1,block=1` 并自动打开 RoPE 查看器。
- 实际：当前只完整导出第 0 层，查看器按步骤选择 L1，因此只能显示“RoPE 细节只在第 0 层完整导出”，无法查看该步要讲的旋转后 K。
- 原因：课程定位与真实数据采集范围没有一致约束；既有课程检查主要覆盖可推进和答题状态。
- 修复建议：该步定位到已有真实数据的 decode L0，或在另行核对后采集所需 L1；为所有自动打开局部面板的课内步骤验证数据实际可用。
- 验证：静态课程扫描只发现这一个非第 0 层的完整张量查看步骤；直接调用其读取路径得到上述缺失错误。见 `course-gaps.json` 和 `content-probes.json`。

### R4 · P2：Llama 局部查看器打开后没有接管键盘焦点

- 位置：`GPT2-LLaMA-Atlas/js/llama-local-viewer.js:82–102`；Escape 仅在第 77–78 行监听 host 内事件。
- 触发：聚焦顶栏“真实张量”，按 Enter 打开查看器，然后按 Escape。
- 实际：焦点仍停留在背景 `btn-real-data`，Escape 没有关闭查看器。虽声明 `aria-modal=true`，打开时没有聚焦内部控件，也没有 Tab 边界和关闭后焦点恢复。
- 原因：查看器只切换 hidden/class；背景仍接收键盘事件，外层全局 Escape 分支也不处理 llamaLocal。
- 修复建议：保存触发元素、打开后聚焦内部、管理 Tab 与背景可操作性、统一 Escape，并在关闭后恢复焦点。覆盖键盘从入口打开以及课程自动打开两种情况。
- 验证：浏览器实际聚焦 id=`btn-real-data`、inViewer=false，随后 Escape 后查看器仍可见。

### R5 · P2：GPT-2 来源说明仍将真实数据称作教学模拟

- 位置：`GPT2-LLaMA-Atlas/js/main.js:1424`。
- 触发：GPT-2 真实轨迹已经 ready，点击“来源”。
- 实际：仍写“注意力权重、token id 与概率是教学模拟”，与当前真实回放、独立核对结果矛盾。
- 原因：来源文案只针对 SmolLM2 实时选择新说明，所有其他入口沿用旧模拟文案。
- 修复建议：按实际模型和当前轨迹模式说明来源；把主实例实测值、独立手算模拟、参数计算和论文配置分开标识。
- 验证：浏览器采集到完整旧文案，见最终浏览器报告 `GPT2 sources describe real values`。

### R6 · P2：decode 的 RMSNorm 仍提供 5 个位置选项，实际全部读同一行

- 位置：`GPT2-LLaMA-Atlas/js/llama-local-viewer.js:222`。
- 触发：进入 `fwd1.block0` 的 decode，打开 RMSNorm 并切换“位置”。
- 实际：当前 T=1，选择框仍固定显示 0—4。读取函数将越界值夹到 0，因此选择 1、2、3、4 都显示同一行数据；用户以为切换了位置，但实际没有。
- 原因：选择框硬编码 prefill 长度 5，而不是由当前张量 T 产生。
- 修复建议：按当前前向位置数生成选项，显示或明确关联绝对位置；若只有一个位置则只给出该项，不默默夹到另一项。
- 验证：浏览器在 decode 中实际有 5 个 option；独立读取 selected 0—4 均得到实际 row=0。见 `content-probes.json`。

### R7 · P2：SmolLM2 选中层缺少“跳到本轮该层”及执行状态

- 位置：`GPT2-LLaMA-Atlas/js/main.js:458`、`469`。
- 触发：结构树选中 `smollm2.L4`，时间轴仍在本轮 L0。
- 实际：右侧只显示“当前步骤不直接经过此对象”，没有原先已有的跳到本轮 L4 按钮，也不能区分该层已执行还是未执行。
- 原因：两处模型节点正则仍只接受 `gpt2|llama2`，不识别新增 smollm2。
- 修复建议：使用当前模型和节点元数据识别层；至少补齐新模型匹配，并在三个模型身份下检查选择与跳转。
- 验证：真实浏览器选中 L4，`#jump-layer` 数量为 0，右侧文本为上述回退说明。
