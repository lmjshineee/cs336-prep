1. 因果掩码反例：让模型「看到未来」会怎样？
======================================================================
英文新闻段落：1092 个字符 -> 235 个 BPE token
开头 80 个字符：'Astronomers said on Tuesday that a new survey of the southern sky had revealed\nm' ...

同一段文字、同一份权重，只改一个开关 causal：
  causal=True  （正常，位置 t 只能看 0..t）: loss = 3.2987   perplexity = 27.1
  causal=False （去掉掩码，位置 t 能看到整个序列）: loss = 5.9697   perplexity = 391.4
  -> loss 反而上升了 2.6710，困惑度变成原来的 14.5 倍

结果可能和直觉相反：不是「能看到未来 -> 更容易抄答案 -> loss 更低」吗？
对**已经训练好、权重固定**的 GPT-2 来说，去掉掩码只会把它弄坏：

  1) 这 124M 个参数是针对「因果注意力」训练出来的。每个头学到的东西
     （比如 exp2 里那个复制头：把注意力放到 i-period+1 的位置）
     都建立在「只能看左边」这个前提上。
  2) 去掉掩码后，位置 t 的输入里混进了右边的 token，隐藏状态立刻偏离
     训练时见过的分布，144 个头的行为全部改变，预测自然变差。
  3) 所以「同一份权重 + 不同掩码」= 一个不同的函数。掩码不是装饰，
     它是模型定义的一部分（就是你 step04 里写的那行 masked_fill）。

那「训练时不加掩码会导致 loss 异常低」又是怎么回事？
  那是**从随机初始化开始训练**的情况：没有掩码时，模型会学会直接把
  位置 t+1 的 token 信息搬到位置 t（答案就在眼前），训练 loss 可以降到很低；
  但生成时它只能看到前缀，作弊手段失效，效果立刻崩掉。
  两件事不矛盾：一个说的是「固定权重的预训练模型被改坏」，
  另一个说的是「训练时学会了作弊」。想亲手验证后者，见 README 的延伸练习。

2. 随机初始化对照：真权重 vs 随机权重
======================================================================
构造一个 12 层 / 12 头 / 768 维的同结构模型，权重全部随机……
随机权重（GPT-2 官方初始化 N(0,0.02)）: loss = 10.9578   perplexity = 57,402.8   (1.2s)
参考：完全均匀地瞎猜 loss = ln(50257) = 10.8249，perplexity = 50257

真实预训练权重 loss = 3.2987，随机权重 loss = 10.9578，差 7.66 nats/token
用随机权重时，模型对「下一个词」几乎没有任何偏好，所以 loss 就停在均匀分布附近；
真实权重把 loss 压到 3 左右，说明它确实从海量文本里学到了语言规律——
这些数字（124M 个浮点数）不是结构给的，是训练出来的。

顺便一提：如果直接用 PyTorch 默认初始化（nn.Embedding 是 N(0,1)），
loss = 484.9（0.5s，远超 10.83）。
那不是「没学过」，而是初始化尺度不对：嵌入大了 50 倍，logits 爆炸，
softmax 变成几乎 one-hot 的乱猜。所以上面的随机权重按官方初始化 N(0,0.02)。

3. 困惑度表格：GPT-2 眼里的四种文本
======================================================================
中文段落：149 个字符 -> 314 个 token （平均每个字符 2.11 个 token）
Python 代码：761 个字符 -> 380 个 token
随机 token：直接采样 235 个 id（不是文本）

  text type         chars  tokens  tok/char     loss   perplexity  bits/char
  ----------------------------------------------------------------------------
  English (news)     1092     234      0.21   3.2987         27.1       1.02
  Chinese (text)      149     313      2.10   2.8272         16.9       8.57
  Python (code)       761     379      0.50   2.6703         14.4       1.92
  Random (ids)          -     234       nan  12.4678    259,839.0          -

怎么读这张表（这里有一个新手最容易踩的坑）：

  1) 先看 per-token perplexity：中文 16.9 反而比英文 27.1 低！
     直觉会说「中文更难」才对。问题在于「token」不是公平的单位：
     GPT-2 是字节级 BPE，一个汉字要 2.11 个 token；
     而一个汉字的 UTF-8 字节序列本身高度可预测（第一个字节基本确定了后面几个），
     所以「每个 token」看起来很便宜。

  2) 中图把单位换成「每个字符花多少 bit」（bits/char）：
     英文 1.02，中文 8.57，Python 1.92。
     这才是跨分词器可比的数字：同一段中文，GPT-2 每个字符要多花
     8.4 倍的代价——符合「它不是为中文训练的」。

  3) 结论：**不同分词器的 perplexity 不能直接比**。
     比较模型能力要用 bits/char、bits/byte 这类和分词无关的单位，
     或者至少保证两边用同一个分词器。

  4) 同样的坑再来一次：Python 代码每 token 的 ppl 只有 14.4，
     但按字符算 1.92 bit，反而比英文新闻（1.02）贵。
     因为代码的 token 更短（0.50 tok/char 左右，缩进、标点都被单独切出来），
     「per-token 更低」不代表「按字符更便宜」。

  5) 随机 id 的 ppl 约 259,839，比「均匀瞎猜」的 50257 还高：
     模型被训练得偏向自然语言，随机 id 反而落在分布外，属于最坏情况。

5. 训练期的掩码反例：从零训练两个 1 层小模型
======================================================================
第 1 节是「权重固定、只改掩码」，所以 loss 反而变差。
真正会让 loss 异常低的是「训练时就没有掩码」：答案就在输入里，
模型会学会把位置 t+1 的信息搬到位置 t。

这里用 step08 的训练循环，在约 2KB 英文新闻上从头训练两个完全一样的小模型
（1 层 / 1 头 / 64 维 / 字符级分词器，300 步），唯一区别是 causal 开关：
  模型 A：causal=True（正常）
  模型 B：causal=False（训练时忘了加掩码）

训练完后，两个模型都用「正常的因果方式」评估并生成——
因为推理时你永远只能看到前缀，没有未来可看。

训练耗时：1.3s（两个模型 × 300 步）

  训练 loss（最后 20 步平均）：
    有掩码 A: 2.3086
    无掩码 B: 0.0872   <- 明显更低，因为答案在输入里

  用正常因果方式在验证文本上评估：
    有掩码 A: 2.6074
    无掩码 B: 7.8801   <- 训练时的作弊手段在推理时用不上
    均匀瞎猜基线 ln(43) = 3.7612

  生成对比（同一个开头，贪心解码 16 个字符）：
    有掩码 A: 'The observationst t the the ther'
    无掩码 B: 'The observationssa abveve ta tto'
